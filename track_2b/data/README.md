# Explicitly staged product data

`fixtures/corpus.json` retains the twelve synthetic author-reference families, paired clean/defective forms, exposed development/holdout labels and pending-human-review provenance byte-for-byte. They are engineering controls, not fresh blind evaluation or independent human gold.

`recordings/` retains three older historical final-response projections with unchanged provenance and failures; see [their scope](recordings/README.md). The separately closed [r5 pack](recordings/r5-sparse-candidate/README.md) deliberately adds nine exact runtime evidence files plus its README: original input/request/envelope/content, capture receipt, derived record/provenance, prompt and retained parser source. The parser is inert evidence, not executed by the app. These are selected synthetic-policy examples, not new inference or representative model accuracy. The r5 capture is host-declared, unadjudicated, answer-ineligible and not independently authenticated or human gold. All other private typed receipts, raw evaluation captures, ledgers, reviewer records and other tracks are excluded. Docker admits only the nine fixed r5 runtime paths, never the directory or pack README.

The named keyless [delivery example](../examples/delivery-review/README.md) is entirely authored and never a model response. The item-level licenses are in [DATA_LICENSES.json](../../DATA_LICENSES.json) and [data attribution](DATA_ATTRIBUTION.md). The final package is checked against the conservative 100,000,000-byte data-directory ceiling; count and exact bytes are recorded in the release verification receipt.
